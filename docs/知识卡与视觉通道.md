# 知识卡与视觉通道

> 需要时读。**只在要查卡、写卡、用视觉判断的时候看**。
> 里面是：知识卡怎么写 · 怎么查 · 视觉通道什么时候用。

## 知识卡：一份人写的事实文档

位置 `assets/knowledge/<包名>.md`，跨 App 的系统界面放 `assets/knowledge/_system.md`。

记的是**客观事实、机制、时序、判据口径** —— 人写得出来、也判断得出真假的那种。
**只有人能改**（工具层没有写卡入口）。

> 为什么只写事实：机器采集的实现细节（rid / activity / 坐标）换个版本就失效，
> 而且过期了**看不出来**。事实过期了人一眼能发现。

## 写卡规范

知识卡是**人写给人的**，不是给工具看的操作手册。它回答的是「这个 App / 这个系统
在什么情况下会发生什么、怎么运作、什么算符合预期」。

| ✓ 要写 | ✗ 不写 |
|---|---|
| 现象、机制、公式、层级关系、行为规律 | **工具调用**（`android_act(...)`、`python act.py ...`、任何参数名） |
| 什么时候会发生什么（时序） | **操作步骤**（第 1 步点这里、第 2 步点那里） |
| 什么算符合预期、规格与实现的偏差 | **resource-id、坐标、bounds、像素** |
| 已知缺陷（用户能感知的那个现象） | 会话号、某次执行过程、实测数据叙述 |
| 跨 App 的系统通用行为（放 `_system.md`） | 判定结论（那是每次跑完自己下的） |

写成一句 **"用户能看懂、能用肉眼确认"** 的事实，就对了：

```
✓ 通知向左滑动 = 删除通知；上下竖滑 = 展开 / 收起
✓ 恢复已卸载的预装应用，唯一固定入口是：设置 → 应用管理 → 恢复预装应用
✓ 所有时间选择弹窗都是 Canvas 绘制的，控件不在读屏树里，只能靠看图判断当前值
✓ 触发时刻 = 事件开始时间 − 提醒偏移（任务发生时 / 5分钟前 / 15分钟前 / 30分钟前）
✗ android_act(action="tap", x=1782, y=210, via="rid=iv_more")
✗ 步骤：1. 点右上角更多 2. 点「课程表」 3. 点「导入课程表」
✗ 实测 2026-11-12 跑了 3 次，第 2 次才成功
```

### 第一原则：设备无关

我们会在**不同机型**上跑。数值型的东西换个机型 / 方向就失效，**留着就是误导**。

需要标定时写"**怎么标定**"，不写标定结果。

> 真实教训：卡里记着 `TB323FU / 3040×1904`，实际设备是 `TB522FU / 2560×3840`，
> 所有坐标类内容一次性作废。

### 第二原则：标题 = 检索键

AI 拿到的索引就是各卡的 `##` 标题。标题要能被**交互类型词**搜到：

```
✓  ## 弹窗-首次启动三连    ## 时间选择器-双滚轮    ## 坑-清数据会清掉备份
✗  ## 首次启动的三个弹框（实测 2026-09-11）        ← 带日期
✗  ## 一些踩坑记录                                  ← 叙事式
```

标题里**不要带**日期、用例号、构建号。

### 第三原则：只写"会让人做错或重探"的

- 一条经验一行结论 + 一行依据；过程叙事不进卡
- **过时条目直接删**，让体积收敛

### 谁写：只有人

知识卡**只能人改**。工具层已经没有写卡入口了（原来的 `kb-propose` / `kb-apply`
一套已删除），执行时发现卡与现实不符，走 SKILL.md 的「写进 summary 交给人」。

## 查卡

- 按交互类型词检索，**只读命中小节**，不要整卡读

> `session.py start` / 首个 `android_observe` 会返回 **`knowledge_hint`**：知识卡路径 + 小节索引。

## 沉淀四问（写进卡之前过一遍，全过才留）

1. **换设备 / 换方向还成立吗？** 不成立就不要写
2. **下次会来搜这个词吗？** 搜不到的写了白写；把词补进标题
3. **不写会做错或重探吗？** 常识/显然推论不进卡
4. **是"事实"还是"这次的操作过程"？** 事实（机制、规律、判据）进卡；过程叙事不进

# 视觉通道（android_vision）

> SKILL.md 的附录。**只在需要工具级视觉断言时读**。

## 定位

**对话内执行时，优先用 `android_vision` 工具**——它直接看截图的像素，判颜色/图标/置灰这些 OCR 拿不到的东西。
`vision.py` 是同一能力在**无对话场景**（批量回放、CI 脚本）下的入口，走 bash。

```powershell
& "<toolkit>\.venv\Scripts\python.exe" "<toolkit>\tools\vision.py" --image <png> --prompt "按钮是置灰的吗？回答并给依据"
```

配置在 Web 测试台「视觉模型」页维护，Key 只存 `storage/vision.json`（不入库）。

## 什么时候才需要视觉判断

UI 树（nodes）能表达的，**一律不要用视觉**：

| 目标 | 用什么 |
|---|---|
| 界面是否打开 / 进入了哪个页面 | `activity` 字段 |
| 某个控件是否存在、文字是什么 | `full=true` 的 nodes |
| toast / Canvas 自绘文字 | `android_read`（OCR） |
| **置灰 / 颜色 / 图标点亮 / 视觉样式** | 才需要看图或 vision |

> 视觉模型又贵又慢，且偶发调用失败会把"可见即达成"的目标误判成未达成。

## 结论口径

视觉输出是**辅助判据**，PASS/FAIL 结论仍需结合 dump / OCR 证据。

## 测试连接

Web 测试台「视觉模型」页有「测试连接」按钮，会用当前配置发一次真实请求
（一张 64×64 的小图，服务端要求宽高都大于 10），验证鉴权与模型可用性，并显示耗时与错误类型提示。
